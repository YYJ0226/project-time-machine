# 产品简述

## 一句话定位

Project Time Machine 是一个面向 AI 辅助课程项目的全过程留痕、证据关联与可视化审阅平台。

## 要解决的问题

课程项目的成果通常散落在代码仓库、Issue、聊天记录、测试截图和汇报文档中。最终验收时，老师只能看到“做出来了什么”，却很难低成本判断：

- 需求如何演化；
- 关键技术决策为什么发生；
- 某个功能由哪些提交和测试支撑；
- AI 参与了哪些环节，学生又做了哪些判断；
- 最终演示内容能否回到真实证据。

学生也常在截止日前重新拼凑过程材料，既耗时，也容易遗漏真正有价值的思考。

## 服务目的

平台把开发过程中已经存在的事实组织成一条“项目证据链”，同时服务两个目标：

1. 帮助学生持续记录并复盘项目，而不是结课前临时补材料。
2. 帮助老师快速浏览项目全貌，并能从摘要下钻到可核验的 GitHub 证据。

## 核心闭环

```text
导入公开仓库
  -> 同步 Issue / Commit / Pull Request / 测试
  -> 关联需求、实现与验证证据
  -> 学生确认 AI 归纳
  -> 生成项目时间线
  -> 分享给老师审阅
  -> 导出课程报告与视频脚本
```

## 目标用户

### 主要用户：做课程项目的学生

需要低成本记录开发过程、展示个人贡献，并把 Git 历史转化为可讲述的项目故事。

### 次要用户：课程教师或助教

需要在有限时间内判断项目是否真实、过程是否合理、结果是否经过验证。

## MVP 范围

MVP 只支持当前登录用户拥有的公开 GitHub 仓库，聚焦以下能力：

- GitHub 登录与仓库导入；
- 手动同步 Issue、Commit、Pull Request 和基础测试状态；
- 需求—实现—验证三类证据的关联；
- 按时间和证据类型浏览项目；
- 学生确认后的 AI 摘要；
- 无需登录的教师只读页；
- Markdown 报告和视频脚本导出。

## 明确不做

- 3D 建模、虚拟人或沉浸式三维场景；
- 自动修改 GitHub 仓库；
- 私有仓库接入；
- 团队绩效排名或对学生进行自动评分；
- 把 AI 生成内容伪装成原始开发事实；
- 第一版同时接入 GitLab、Gitee 等多平台。

## 产品原则

1. **事实优先**：原始 GitHub 事件不可被 AI 改写。
2. **可追溯**：摘要和结论尽量关联到可点击证据。
3. **用户确认**：AI 建议只有经学生确认后才进入公开叙事。
4. **隐私克制**：默认不展示完整提示词、Token 和环境变量。
5. **降低负担**：尽量从现有开发活动中采集信息，避免重复填表。

## 首轮成功标准

- 新用户能在 5 分钟内导入一个公开仓库并看到时间线。
- 任一公开结论至少能关联一条来源证据，或清楚标记为学生补充说明。
- 老师在 3 分钟内能理解项目目标、关键转折、最终结果和 AI 使用边界。
- 导出的 Markdown 能作为课程报告初稿，视频脚本能支持一次完整演示。
