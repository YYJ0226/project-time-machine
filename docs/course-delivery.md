## 本地生成准备包

在仓库根目录、使用项目要求的 Node.js 22：

```bash
npm run prepare:course
```

命令要求先提交本阶段改动，且没有未提交或未跟踪文件；它不会自动提交、推送、登录、请求外部 API 或修改数据库。
若拒绝脏工作区，先检查 `git status`，只提交你确认应进入仓库的内容；不要为让命令通过把环境文件加入 Git。

每次生成 `artifacts/course-delivery/kit-<随机后缀>/`，不覆盖旧目录；整个 `artifacts` 已被 Git、ESLint、Vitest 和 Vercel 上传忽略。
目录包含：

```text
START-HERE.md                 使用顺序和未完成事项
manifest.json                 HEAD、分支、生成时间和文件 SHA-256
commit-history.json           HEAD 可达的最近最多 30 条 SHA 与提交时间
README.md
package.json
docs/product-brief.md
docs/demo-script.md
docs/recording-checklist.md
```

只从 `HEAD` 读取上列七个白名单普通文件，不读取 `.env*`、`.git/config`、`node_modules`、浏览器数据、下载目录、真实视频或其他任意文档。
输出路径固定在本仓库，不接受自定义路径，不跟随 `artifacts` 或 `course-delivery` 的目录链接。
已提交文件为符号链接、出现常见密钥模式或完整教师能力链接时停止，报错不打印匹配内容。
扫描只是辅助保护，不保证检测全部秘密；公开前仍需人工检查。

`manifest.json` 最后写入，缺少它的目录说明生成未完成，不可交付。哈希只校验包内文件完整性，不是签名或安全审计。
提交时间不等于劳动时长，最近 30 条不等于全部开发历史；浅克隆也会在清单标明。
本命令不查询线上或 GitHub CI，清单相应状态始终是 `not_checked`，不能据此宣称部署与材料 HEAD 一致。
准备包也不是完整可运行源码，需要代码时使用仓库，而非只提交这个目录。

## 录制顺序

1. 按检查表确认课程要求、账号会话和素材隐私。不要在录制中打开服务商或密钥配置页面。
2. 在正式站点读真实项目，先同步一次，再冻结演示范围；预先打开需求 #3、PR #4 与其对应 CI。
3. 采用番茄钟作为主要实验案例，先完成真实、有用的改进、测试和 Git 留痕，再导入平台；不造历史、不人为拆空提交。平台既有 AI 账本只作明确标注的辅助案例，不冒充番茄钟的 AI 生成记录。
4. 教师匿名页需由本人确认分享范围后新建短期快照。旧测试链接已经撤销，不可作为可用演示入口。录制时隐藏地址栏和完整链接，录后撤销并重新访问核对。
5. 先生成十至十五秒 AI 配音试听和视觉样板，确认自然度、技术词读音、服务费用与画面风格，再生成长音轨并采集真实操作。
6. 回看成片，确认声音、文字清晰、真实来源可核对、没有敏感信息；填写检查表，再决定是否提交。

视频须落在五至七分钟内，优先保留产品痛点、技术方法、真实证据链、AI/事实边界及教师只读闭环，再调整镜头时长；不得靠加速到看不清界面来压时长。
