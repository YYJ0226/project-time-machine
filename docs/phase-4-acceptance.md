# 阶段四：交互时间线与项目回放

本阶段将已同步的真实开发证据放到共享时间坐标上，供学生讲解、回顾项目。
完成后暂停验收；教师免登录分享、AI 摘要与导出属于下一阶段。

## 入口与主要操作

从项目列表或证据工作台点击“时间线与回放”。页面地址为：

```text
/app/projects/<projectId>/timeline
```

- 四条泳道：需求、代码（Commit 与 PR）、验证、AI。AI 当前没有记录，不填充示例数据。
- 总览使用紧凑节点；C 代表提交，P 代表 PR。2×/4× 放大后显示标题，并允许横向滚动。
- 同时刻或相近事件垂直错层，保持真实横向时间位置。
- 可按类型、标题/正文/提交 SHA、起止日期、关键节点组合筛选。
- 日期以北京时间（UTC+8）计算，包含结束日期当天；反向日期会提示错误。
- 点击节点或使用“定位事件”下拉框打开详情，可查看正文、状态、时间含义和 GitHub 原文。
- 侧栏只导航人工已确认的关系；青线只连接选中事件与其已确认关联。跳转至被筛掉的事件时会重置筛选。
- “复制事件链接”复制带 `?event=<eventId>` 的定位地址，刷新后仍定位该事件；它不是免登录分享链接。

## 回放与录屏

- 上一条、下一条和进度条均沿当前筛选结果按时间顺序移动。
- 自动播放支持每 1、2.5、5 秒一条，到末尾自动停止。末尾再次播放从第一条开始。
- 空结果与单事件禁用自动播放；改变筛选或手工选中事件会停止播放。
- 时间线画布中的左右方向键选择前后事件，Home/End 定位首尾。
- 聚焦讲解隐藏筛选与页头干扰，保留图、详情和播放器；Esc 可退出，Tab 焦点限制在视图内。
- 系统启用减少动态效果时，关闭平滑移动和自动播放，保留单步浏览。

## 关键节点与时间含义

关键节点来自确定性源状态：最早记录、已合并 PR、已关闭需求、失败/超时/取消的验证。
它们是浏览线索，不是 AI 推断的“重大决策”。

| 记录 | 当前时间字段含义 |
| --- | --- |
| Issue | 关闭时间，或最近更新时间 |
| Commit | 作者时间，缺失时使用提交者时间 |
| PR | 合并、关闭或最近更新时间 |
| CI | workflow run 最近更新时间 |

所以一条需求的时间可能晚于实现提交，CI 也可能先于 PR 合并完成。
页面解释这些差异，不重写时间来凑出理想故事。状态是最近同步快照；
回放不声称重建当时全部项目状态，也不会切换仓库版本或恢复历史代码文件。

## 建议的三分钟验收脚本

1. 前 40 秒：看四条泳道，使用“定位事件”选择 PR #4，核对时间、状态和原文。
2. 40—90 秒：沿已确认关联进入需求 #3、提交和 CI，分别查看详情或打开原文。
3. 90—120 秒：放大时间坐标，再试搜索 SHA 或仅关键节点筛选。
4. 最后一分钟：进入聚焦讲解，播放几条记录，拖动进度条，暂停并退出。

这是供用户验收的操作提纲，尚未进行陌生用户的三分钟可用性计时测试。

## 数据与权限边界

- 服务端验证登录、项目 owner，并继续依赖数据库 RLS；本阶段没有扩大 GitHub 授权权限。
- 最多加载最近 1000 条证据和 1000 条已确认关系，超过上限会提示，不以不完整数据冒充完整历史。
- 不能解析的时间会从坐标中排除并提示数量，空数据、相同时间与密集事件由纯函数测试覆盖。
- 时间线只读本地加载的快照。返回证据工作台同步后，再重新打开时间线获取新数据。
- 当前自动化测试主要覆盖数据和几何逻辑，交互联调使用真实浏览器；多账号 RLS 与无障碍专项审计仍属于质量加固工作。
