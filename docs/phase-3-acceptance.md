## 已完成的流程

1. 通过 GitHub 登录，从 `/app` 打开课程项目的证据工作台。
2. 点击“同步 GitHub 证据”，读取 Issue、主分支 Commit、Pull Request 和 Actions workflow run。
3. 查看需求、实现和验证三条轨道，展开证据详情，或打开 GitHub 原文。
4. 根据 Issue 编号与提交 SHA 生成关系建议，由用户确认或忽略。
5. 已确认与已忽略关系均可继续浏览、打开两端原文，或撤销审阅回到待确认区。
6. 再次同步并刷新，人工决定保持不变；按唯一标识写入，已有证据不重复创建。

轨道默认显示最近 12 条，更多记录可展开。每次同步最多采集每类最近 100 条，
当前 Commit 接口读取默认分支，并非仓库的全部分支或完整历史。

## 故障与回归验证

- 真实触发 GitHub 匿名 API 请求额度限制：显示同步失败及原因，已有证据和审阅结果未丢失。

## 当前边界

- CI 表示 GitHub Actions 的运行状态，不解析测试覆盖率或逐条测试报告；成功不等于软件没有缺陷。
- 规则评分用于排序，不代表概率；系统不会自动把建议变成事实。
- 只有原文中明确的编号引用或相同 SHA 才建议关联，缺少这些线索时不会强行补链。
- RLS 策略和服务端用户/项目过滤已实现，多账号云端隔离的专项验收仍待补充。
- 未配置只读 `GITHUB_TOKEN` 时，匿名请求额度容易耗尽。可等待额度恢复，或按配置文档设置自己的只读 Token。
- 数据同步保留历史快照，不因原文删除或可见性变化而自动删除既有证据；同步前仍会重新核验仓库可见性和所有权。
- 可交互时间线、AI 摘要、教师分享与导出属于后续阶段，本次未实现。
