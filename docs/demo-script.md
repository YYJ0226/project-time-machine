以下为待制作初稿。番茄钟改进及新导入演示尚未执行，实验段必须用实际提交、测试和页面结果定稿；不应现在就生成一段“实验已完成”的音轨并当成结果交付。
截图必须来自真实软件；概念图、演示时长和剪辑均明确标注。首个有声样板验收后再扩展整片。

## 00:00–00:50 动机：完成软件，不等于讲清过程

画面：先展示番茄钟，再将需求、代码提交和测试分散到画面中，最后汇成一条证据线。开场概念动画标为示意，不捏造仓库事件。

口播：

课程项目做完以后，我们通常能展示一个可以运行的软件，却不容易讲清它是怎样一步步完成的。
比如一个番茄钟：为什么增加这个功能，哪一次提交实现了它，修改之后有没有测试？
答案往往散落在需求、提交记录和截图里。
学生需要在结课前重新拼材料，老师也很难从最终演示判断开发过程。
Project Time Machine 想解决的，就是让这些已经存在的记录重新连起来：既看得到结果，也能追溯过程。

## 00:50–01:20 需求：学生能整理，老师能核验

画面：真实首页“进入工作台”，转到两条角色路径。首页右侧保留“样例数据”标识。

口播：

平台面向两类使用者。
学生连接自己的公开仓库，把需求、实现和验证组织成一条可回看的时间线。
老师不必阅读所有代码，也不用额外注册，就能通过只读快照查看项目，并从结论回到 GitHub 原始记录。
因此，它不是另一个代码托管平台，也不是给学生自动打分的系统。
它做的是开发证据的组织、解释和审阅。

## 01:20–02:20 技术路线：事实层与 AI 归纳分开

画面：按口播逐步展开架构；GitHub 数据流为主干，AI 旁支单独着色。证据、关联、AI 账本和教师快照四个层次不要一次全部堆上屏幕。

口播：

实现上，平台采用 Next.js 作为网页和服务端入口，Supabase 负责身份认证与数据保存，GitHub 提供公开仓库证据。
用户登录后，服务端核对身份和仓库归属，再手动采集 Issue、提交、拉取请求和持续集成结果。
这些信息先保存为原始证据，再根据编号引用和提交标识提出关联建议。
建议不是事实，用户核对后才变成已确认关系。
时间线负责把记录放到共同的时间坐标上，支持筛选、定位和回放。
AI 则是旁路：根据有限证据生成摘要和讲解初稿，调用与审阅状态分别留痕。
只有人工确认的文字才能进入交付，原始证据不会被 AI 改写。
每个受限页面和写操作仍要在服务端检查权限，不只依靠隐藏按钮。

## 02:20–02:50 实验设置：用番茄钟解释平台

画面：番茄钟基线和改进版本分栏；每个版本标注真实 SHA。此段待案例实际开发后录制。

口播：

为了让平台的价值更直观，我们用一个番茄钟项目作为案例。
它原本已经可以开始、暂停、重置，以及切换工作和休息时间。
实验不追求把它改成第二个大型平台，而是选择几个真实的小需求，完成改进、测试和正常的 Git 提交。
接下来观察：平台能不能把一次改动的动机、实现和验证串起来，并让老师找到来源。

## 02:50–04:55 实验展示：从一次需求走到可核验证据

画面：按真实开发结果确定 P1／P2／P3 最终范围。先展示番茄钟的一次改进前后，再在 PTM 中打开对应需求、实现、测试和时间线；不连讲三套重复点击。
短倒计时必须标注“演示时长”，测试结果和计数以拍摄时版本为准。

待实验通过后的口播草案：

先看设置输入。
用户输错时长时，软件应明确提示，而不是破坏当前设置或使倒计时异常。
这条需求对应一个真实 Issue；修复前先建立边界用例，再完成校验和修复。
之后，再围绕暂停、重置与模式切换检查计时状态；如果加入完成记录，也要验证关闭重开和异常文件的处理。
每一批改动都对应实际代码和测试，不是为了增加历史数量而拆空提交。

接着，把这个仓库导入 Project Time Machine。
同步后，需求、提交、拉取请求和持续集成结果出现在同一个证据工作台。
选择刚才的需求，可以找到相关实现建议。
核对两端的原文后确认关联，就得到一条从需求到实现、再到验证的链。
点开 GitHub 原文，仍能看到真正的代码变更或检查结果，而不是只有平台自己的说明。

然后进入时间线。
我们可以只保留提交事件，定位到这次修改，再查看相关需求与测试。
用回放顺序浏览，会更容易理解功能是怎样逐步演变的。
这里回放的是已经采集的记录，不是恢复历史文件系统；页面上的状态也对应采集时刻。
实验重点不在于提交数量，而在于这一次改变能否被解释和核验。

## 04:55–05:40 AI：有归纳，也必须保留边界

画面：番茄钟的真实草稿状态；如需展示已有历史 AI 提示，明确切换“平台自身辅助案例”，不能混成同一仓库。

口播：

AI 可以帮助整理文字，但不能成为原始事实的替代品。
如果这个新案例没有生成并确认摘要，教师页就只展示原始证据，不能拿别的项目内容填进去。
平台自身的既有 AI 记录还展示了另一种风险：生成时的输入范围可能与后来同步的证据不同。
因此，交付页、教师页和下载材料都会提示生成时间、样本条数与历史版本。
所谓缺失证据，也只是这个样本没有显示，不能据此断言相关工作没有做过。
本次演示不冒充新 AI 调用，也不会为了镜头重新审批已有文字。

## 05:40–06:15 交付：老师独立审阅，学生控制分享

画面：本人确认范围后新建短期教师快照，无登录窗口查看，再撤销并刷新。全程隐藏完整分享地址。展示两种下载文件的标题与版本提示，不打开私人下载目录。

口播：

最后，学生可以把当前内容发布成有期限的固定只读快照。
老师不需要登录，就能查看公开证据和已确认文字，并继续打开来源。
快照不会随着后续编辑悄悄改变；持有链接的人都能访问，所以分享前要确认范围，也可以随时撤销。
撤销后新访问会被拒绝，但已经下载的文件不能召回。
平台还提供 Markdown 报告和视频讲解提纲，帮助整理课程交付材料。

## 06:15–06:30 结论与局限

画面：源码仓库、正式入口与三条结论；不展示教师能力链接。收尾留停顿，避免话音未落就切黑。

口播：

Project Time Machine 把分散的开发记录组织成可解释、可追溯、可交付的证据链。
本次是功能性案例展示，不是用户研究或准确率实验。
当前仍限定公开仓库、有限采集范围，并依赖人工核对。
源码、测试和未完成事项都保留在仓库中，方便继续验证和改进。

## 配音与剪辑规则

- 先用开场十至十五秒试听中文 AI 音色，再生成长稿；不克隆真人，不默认调用付费模型。
- 稿件中的英文名、PR、CI 和提交标识统一读法；完整 SHA 放画面，不逐字符念出。
- 字幕根据最终音轨对齐，不把上面时间预算当成逐字时间戳。
- 原始画面和必要剪辑可以结合，但演示不能伪造点击结果、隐藏版本提示或把示意动画说成真实运行。
- 收尾回看成片与检查表，核对 300–420 秒、文字清晰、音画一致、无秘密；目前这些尚未执行。
