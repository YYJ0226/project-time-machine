# 视觉方向：软件项目观测站

## 核心隐喻

界面不是传统管理后台，而是一座“软件项目观测站”。用户面对的是项目留下的事件信号：需求出现、代码变化、测试通过、AI 参与。中央时间轴像观测仪器，把分散记录对齐到同一时间坐标。

## 设计令牌

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| Deep orbit | `#07111F` | 页面主背景 |
| Instrument | `#0D1C2C` | 观测窗口与导航表面 |
| Frost | `#EAF2F5` | 主要文字与高亮刻度 |
| Periwinkle | `#8B91FF` | 需求与主操作信号 |
| Signal amber | `#F2B84B` | 决策、等待与重要节点 |
| Trace cyan | `#64D8D1` | 测试、同步与已验证状态 |

字体使用 Geist 处理拉丁字符和数据，中文回退到系统无衬线字体。等宽字体只用于提交哈希、时间戳和证据编号。

## 布局草图

```text
+-----------------------------------------------------------+
| PTM / 项目观测站                文档   GitHub   阶段 01/06 |
+-------------------------+---------------------------------+
| 项目为什么需要时间机器  |          观测窗口               |
| 简短定义与当前阶段      |  需求 ---------●--------------- |
|                         |  代码 ----●---------●---------- |
| [查看阶段计划]          |  验证 --------------●---------- |
|                         |  AI --------------------○------ |
+-------------------------+---------------------------------+
| 事实 / 人工说明 / AI 草稿 / 已确认叙事 的边界说明         |
+-----------------------------------------------------------+
```

桌面端采用左侧叙事、右侧观测窗口的不对称构图；移动端改为单列，时间线保持横向语义但减少装饰刻度。所有内容左对齐，只有观测窗口中的节点遵循时间坐标。

## 交互原则

- 动效用于表现“信号被捕获”，而不是让每张卡片漂浮。
- 颜色编码必须同时配合文字或形状，不能只靠颜色传达状态。
- 键盘焦点清晰可见；尊重 `prefers-reduced-motion`。
- 页面文案优先解释用户能看到什么，不使用空泛营销词。
- 观测窗口是唯一高视觉强度区域，其余界面保持克制。

## 第一阶段范围

阶段一只建立视觉语言和静态界面骨架。示例时间线用于验证信息层级，不代表仓库同步、AI 或教师分享功能已经完成。
