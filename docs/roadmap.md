# 分阶段路线图

每个阶段都以“可运行、可演示、可提交”为结束条件。当前阶段验收通过前，不进入下一阶段。

## 阶段一：工程与产品基线

目标：让项目从空仓库变成可运行、可持续开发的工程。

- 明确产品定位、用户、MVP 和不做事项；
- 建立 Next.js、TypeScript、Tailwind CSS 工程；
- 完成现代化首页与视觉方向；
- 配置 Issue、Pull Request 模板和 CI；
- README 记录运行方式、路线图和 Git 规范。

验收条件：

- `npm run lint` 和 `npm run build` 通过；
- 首页在桌面端和移动端可读；
- GitHub 仓库中能看到有意义的分步提交；
- 文档足够让同学或老师理解平台要解决的问题。

## 阶段二：登录与项目导入

目标：用户能安全登录，并创建第一个项目。

- Supabase 项目与数据库基线；
- GitHub OAuth 登录、退出和会话恢复；
- 获取用户拥有的公开仓库；
- 项目导入向导；
- 空状态、错误状态和基础权限校验。

验收条件：使用真实 GitHub 账号导入一个本人拥有的公开仓库，刷新后项目仍然存在。

## 阶段三：证据同步与关联

目标：形成最小可用的项目证据链。

- 手动同步 Issue、Commit、Pull Request 和测试状态；
- 统一事件结构并保存同步记录；
- 基于引用、分支名和提交信息给出关联建议；
- 用户确认、修改或拒绝关联；
- 证据详情与 GitHub 原文链接。

验收条件：选定一个真实功能，能从需求一路追溯到实现提交和验证结果。

## 阶段四：项目时间线

目标：让复杂开发历史变得可浏览、可解释。

- 需求、代码、验证、AI 四条泳道；
- 时间缩放、筛选、定位和详情面板；
- 关键里程碑与转折点；
- 响应式浏览和键盘可访问性；
- 适用于视频讲解的聚焦模式。

验收条件：陌生用户可在 3 分钟内理解示例项目的主线，并打开至少三类真实证据。

## 阶段五：AI、教师审阅与导出

当前状态：已验收并合并。范围及测试记录见 [阶段五验收说明](phase-5-acceptance.md)。

目标：完成从过程记录到课程交付的闭环。

- DeepSeek 生成阶段摘要、缺失证据提醒和讲解草稿；
- AI 任务账本及人工确认流程；
- 可撤销的教师只读分享链接；
- Markdown 报告导出；
- 视频讲解脚本导出。

验收条件：老师无需登录即可审阅；AI 文本有明确标识；导出内容可直接作为报告和录屏提纲的初稿。

## 阶段六：质量加固与发布

本阶段按检查点逐次验收，完成后暂停：

- A：质量加固、隔离生产 HTTP 回归、配置检查、发布／回滚手册和录屏讲稿。
- B：本人完成 Vercel 账号授权后部署，联调真实生产 OAuth 和教师分享。已验证证据同步、时间线、下载、匿名分享／撤销、关联审阅写入和退出后门禁；首页登录入口已修复上线。排除并发操作后的会话恢复与 AI 人工审阅写入仍待复核；手机／其他网络按本人要求延期，见[检查点 B 记录](phase-6b-acceptance.md)。
- C1：准备可排练的分镜、录制检查表与本地白名单资料包；已完成准备工具，不代表已录制视频。
- C2a：番茄钟 P1 设置校验、测试／修复／CI 及官方视频技能安装已完成，本人桌面验收通过。本人随后指定视频改用平台自身案例，停止番茄钟 P2/P3。
- C2b-1：平台自案例脚本、独立十五秒 Remotion 概念开场与离线合成占位配音；当前检查点完成后暂停，等待样片视觉／节奏验收。尚无最终神经 AI 音轨或 MP4。
- C2b-2：用免费或现有额度确认最终 AI 音色，再真实录制平台实验与整片。任何收费先询问；示意图不冒充录屏，自案例不当作平台自证正确。
- C3：成片验收后再决定正式版本发布。手机验收仍按本人要求延期。

只完成 A 不表示已上线，也不表示演示视频已经录制。详见[检查点 A 验收](phase-6a-acceptance.md)。

目标：让课程演示稳定、可信、可复现。

- 单元、集成和端到端测试；
- 性能、可访问性与安全检查；
- 部署、监控和故障降级；
- 演示数据、演示脚本和最终视频；
- README 收尾与版本发布。

验收条件：线上地址稳定可访问，关键流程有自动化测试，按脚本可完成一次无中断演示。
